# Code of Conduct

## Purpose

Nila is an open-source project intended to support productive technical collaboration. Everyone participating in project spaces is expected to communicate professionally, respect other contributors, and help maintain an environment where technical disagreement can be handled constructively.

## Expected behavior

Participants should:

- Be respectful, patient, and constructive.
- Focus criticism on ideas, code, designs, and observable behavior rather than individuals.
- Provide actionable technical feedback when requesting changes.
- Respect different levels of experience and different communication styles.
- Credit the work and ideas of others appropriately.
- Respect privacy, confidentiality, and responsible security disclosure practices.
- Accept reasonable maintainer decisions about scope, architecture, security, licensing, and repository standards.

## Unacceptable behavior

The following behavior is not acceptable in project spaces:

- Harassment, intimidation, threats, stalking, or sustained personal attacks.
- Discrimination or derogatory comments based on personal characteristics or identity.
- Sexual harassment or unwanted sexual attention.
- Doxxing, publishing private information, or attempting to expose another person's identity without permission.
- Deliberate disruption, spam, trolling, or repeated off-topic hostility.
- Impersonation, deceptive attribution, or knowingly false claims about another contributor.
- Publishing confidential security reports, credentials, private data, or exploit details contrary to the security policy.
- Repeatedly ignoring maintainer instructions intended to protect contributors or the project.

## Scope

This Code of Conduct applies to repository discussions, issues, pull requests, reviews, documentation, community spaces, and other interactions where a person is representing or participating in the Nila project.

## Reporting conduct issues

Do not escalate interpersonal conflicts through public harassment or retaliation. When possible, report conduct concerns privately to the project maintainers with relevant links, context, and evidence.

Security vulnerabilities must be reported through the process in [SECURITY.md](SECURITY.md), not through public conduct reports.

## Enforcement

Maintainers may edit or remove content, close or lock discussions, reject contributions, restrict participation, or take other proportionate action when behavior violates this Code of Conduct.

Enforcement decisions should consider severity, context, prior behavior, risk to participants, and the health of the project. Retaliation against someone who reports a concern in good faith is itself unacceptable.

## Good-faith technical disagreement

Technical disagreement, strong review feedback, rejection of a proposal, or enforcement of project standards is not by itself misconduct when communicated professionally and without harassment.

By participating in Nila project spaces, contributors agree to follow these standards.
